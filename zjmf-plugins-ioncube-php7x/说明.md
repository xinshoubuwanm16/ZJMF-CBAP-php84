# ionCube 加密插件包（需 PHP 7.x 运行环境）

本目录是从 <https://github.com/aazooo/ZJMF-CBAP-plugins> 移植的插件中，**无法在 PHP 8.4 下运行**的那一组，共 **38 个包、675 个加密 PHP 文件**。
它们已按智简魔方 V10 的目标目录结构原样摆放，可直接覆盖到 **PHP 7.x** 站点使用；**不要**复制进 `zjmf-10.4.6-php84/`。

## 一、为什么不能并入 PHP 8.4 版本

这些文件由 **ionCube Encoder for PHP 7.2** 生成（首行标记 `<?php //004fb`）。ionCube 的运行时代码按「加密器代次」校验，Loader 15.x（PHP 8.4/8.5）会直接拒绝 7.x 代次的产物，这不是 Loader 版本问题，也不是可以通过改代码解决的问题：

```
Fatal error: Only files produced by either the PHP 8.2 or 8.3 or 8.4 ionCube Encoders can run on PHP 8.4 or 8.5.
```

本次逐包验证（在本机同一套 Loader 上做的对照实验）：

| 环境 | Loader | 结果 |
| --- | --- | --- |
| PHP 8.4.19 NTS + ionCube Loader 15.5.1 | `ioncube_loader_win_8.4.dll` | 38/38 个包被明确拒绝，无一例外 |
| PHP 7.4.33 NTS + ionCube Loader 13.x | `ioncube_loader_win_7.4.dll` | 675/675 个加密文件解析通过（`php -l`）|
| PHP 8.1/8.2/8.3 + 对应 Loader | 14.x 系列 | 同样拒绝（这些 Loader 会把原因直接写成「须由 PHP 8.2/8.3/8.4 Encoder 生成」）|

要让这批插件跑在 PHP 8.x，只能由原作者用 **PHP 8.x 版 ionCube Encoder 重新加密发布**；第三方无法解密重编。

## 二、目录结构

```
zjmf-plugins-ioncube-php7x/
├── public/plugins/addon/<插件目录>/     # 覆盖到站点同路径
├── public/plugins/server/<模块目录>/    # 覆盖到站点同路径
├── public/web/mf101/                    # 官网主题，覆盖到站点同路径
├── _manifest.json                       # 包名 -> 目标相对路径 -> 文件统计
└── 说明.md                              # 本文件
```

## 三、在 PHP 7.x 站点上的启用步骤

1. 确认站点 PHP 版本为 **7.2 / 7.3 / 7.4**（与加密代次匹配；7.4 已实测）。
2. 安装匹配 VC 版本与线程模型（NTS/ZTS）的 ionCube Loader，并在 `php.ini` 用 **`zend_extension=`** 加载（不是 `extension=`）：
   ```ini
   zend_extension=/全路径/ioncube_loader_win_7.4.dll
   ```
3. `php -v` 应显示 `with ionCube Loader vXX`；`php -i | grep ioncube` 可复核。
4. 把本目录下的 `public/` 内容按原层级覆盖到站点根目录，然后在后台「应用 → 插件」里安装启用。
5. 覆盖前先备份站点原有同名目录；本目录中的文件与上游发布版本**逐字节一致，未做任何修改**。

## 五、和 PHP 8.4 版本的关系

- 插件仓库共扫描到 **82 个包**；其中 **44 个为明文**，已移植进 `zjmf-10.4.6-php84/` 并完成 PHP 8.4 适配（实际落盘 43 个包，另有 `gateway/wx_pay` 因与系统自带同名目录冲突而跳过，详见改造报告）。
- 本目录是余下的 **38 个加密包**，保持上游原样、零修改。
- 二者互补：PHP 8.4 站点用前者，PHP 7.x 站点可同时使用前者与本目录。

## 六、验证边界（说清楚在哪里做的、做到了哪一步）

**已验证**（本机 Windows，PHP 官方 NTS 构建 + 官方 ionCube Loader，命令行 `php -l`）：
- 675 个加密文件在 PHP 7.4.33 + Loader 13 下全部解析通过；
- 38 个包在 PHP 8.4.19 + Loader 15.5.1 下全部被拒绝，报错文本一致；
- 本目录文件与上游发布版逐字节一致（复制过程为二进制拷贝，未换行、未编码转换）。

**未验证**（受本机条件限制，未做）：
- 未在本机搭 PHP 7.4 的完整站点，把这 38 个包**安装进数据库并跑通业务页面**——只做到了「Loader 能解析」这一层；实际业务还需原作者的授权校验（部分包含 `auth.php`）与外部接口，无法保证；
- 未验证这些包在 PHP 8.2/8.3 上的表现（同上，Loader 会因代次不符直接拒绝，结论应与 8.4 一致，但没有逐包实测）；
- 未验证各包的业务功能是否与上游文档描述一致。
